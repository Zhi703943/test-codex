# Upelf 亚马逊运营工作台

纯静态 HTML + CSS + JavaScript 项目，无运行依赖、无需安装或启动服务。

## 打开方式

直接用浏览器打开项目根目录的 `index.html`，并保留旁边的 `public` 文件夹。也可将整个目录上传至支持静态网站的平台，入口为根目录 `index.html`。所有资源使用相对路径，支持子目录部署。

所有功能均在浏览器执行，使用普通脚本而非 ES module，不依赖 fetch 或后端接口。浏览器若限制本地文件存储，请使用应用内的 JSON 导出/恢复功能保存工作数据；不同文件路径下的数据存储行为取决于浏览器。

## 使用流程

1. 在「产品与变体」核实颜色、店铺、父体映射。产品资料来自历史讨论，不代表当前状态。
2. 在「报表数据中心」下载模板，将原始明细映射为标准 UTF-8 CSV 后导入。日期为统计日，金额统一美元；缺失值留空，不放汇总行。每次导入替换全部报表，建议至少包含 28 天。
3. 选择店铺、站点、广告类型、归因口径和截止日。最近 14 天与此前 14 天不重叠，上周滚动 14 天重叠 7 天。
4. 在「搜索词执行表」审核动作，填写目标、匹配、层级及证据，导出人工执行清单。CSV 不是 Amazon 批量上传格式，不会自动修改广告。
5. 在「决策与验证」记录事实、假设、正反证据、动作和复核标准。在事件簿记录外部因素。

数据只保存到当前来源的浏览器 localStorage，不发送至服务器。不包含账号、多人同步、Amazon API 或自动报表下载。换浏览器、换域名或清除浏览器数据不会自动恢复，请定期导出 JSON 备份。备份含业务数据，请妥善保管。

没有自然排名、同口径总销售额、业务报告时，不推断自然订单或 TACOS。归因回补完整性需人工确认。不能从活动级位置汇总推断单词表现。所有动作需人工审核。

每个云任务已隔离，后续开发使用现有 checkout，无需另建 Git worktree。

## 可选开发验证

已有 Node.js 的开发者可运行 `npm test`，仅用于逻辑测试。使用工作台不需要 Node.js。
