# 亚马逊运营工作台

纯静态 HTML、CSS、JavaScript。直接打开根目录 `index.html` 或托管整个目录；无需启动服务、安装依赖或构建。所有运行资源本地附带，不连接 Amazon API，不修改亚马逊后台。

## 四个入口

- **上传报表**：拖入多份原始 CSV、TSV、XLSX 或 ZIP，自动识别并整理，点击一次「开始分析」即保存就绪文件并切页。
- **每周分析**：本周重点、投放关键词、顾客搜索词、广告位。范围和日期统一设置，明细默认紧凑，点击词展开。
- **调整记录**：只必填对象、做了什么、日期，备注选填。历史决策、事件、旧建议完整保存在展开归档中。
- **产品资料**：原 Upelf 四条产品线及全部已有信息保留，可管理其他品牌/店铺/产品。产品名称必填，其余可逐步补充，不影响报表分析。

## 正常流程

1. 上传后台原始报表，不需要先下载模板。
2. 文件中的类型、字段、广告产品和日期可靠时直接采用。店铺/站点记住上次选择；当前归属明确显示，可切换。缺少相同信息的文件只统一补充一次。
3. 只显示文件、类型、日期、状态。映射、原始预览、币种更正、版本和原文件下载均在「高级设置」。同列名组合的手动映射同步到本批同格式文件，并保存规则供下次使用。
4. 点击「开始分析」，只保存就绪文件。个别解析/校验失败的文件保留原因和重试入口，不拦住其他数据。
5. 先查看最多5项有证据的重点，点击直接定位明细；按需要搜索、排序或筛选，然后导出Excel。

XLSX读取非空工作表；CSV支持UTF-8、UTF-16 BOM、GB18030和常见分隔符。原始重复列名按列位置保留，不覆盖数据。旧式 `.xls` 请另存为 `.xlsx`，无需填写模板。单文件30MB，本批读取/解压80MB，ZIP最多50成员，不递归解压ZIP。

归因窗口从实际字段识别，不能识别时标为未知，不强迫用户写专业口径；未知归因下订单、销售额、CVR、ACOS等跨期判断暂停，曝光/点击/花费仍可观察。文件名和工作表名只辅助识别明确的SP/SB/SD产品名称，不凭文件名假定字段或统计日期。广告活动创建/结束日期及导出日期不等于统计周期。

## 每周分析与规则

默认优先采用有完整数据的最近7天，与此前7天比较，排除尚未结束的当天；支持14天和自定义不重叠周期。始终显示实际日期。只有完整周期汇总时，明确回退到整段汇总并提示不能拆周。上期缺失不补零。

重点与行详情由同一个本地规则引擎生成，明确标注「自动计算与规则分析」，没有接入AI。不同组合有不同检查方向：

- 曝光下降、CTR/CVR稳定：检查流量获取，不能直接说预算不足。
- 点击增加、订单未同步、CVR下降：检查流量构成与转化。
- CPC上涨、CVR改善：结合ACOS核对成本收益，不仅因CPC上涨就降价。
- 精准候选必须同时有出单、达到已配置产品目标、人工确认相关性及完整投放报告中无同组精准覆盖的证据；否则只提示观察和补证据。

每项引用实际本期/上期数值，区分观察与建议检查，不把相关性当因果。没有足够变化时不凑数生成重点。低于30次点击仅作低样本提示，不是异常判定或自动否词阈值。

关键词与搜索词分开。默认列为词、活动/广告组、曝光、点击、CTR、CPC、订单、CVR、花费、ACOS；变化显示数值或百分点。完整两期指标、来源、限制和调整入口在展开行中。搜索词支持汇总/广告组明细；汇总清楚标为跨组汇总，不能直接生成无操作位置的执行记录。

筛选支持花费前25%、CPC上涨、CVR下降、新增出单、有花费未出单；搜索词另有出现状态、精准候选与相关性检查。筛选规则在页面说明，不把低样本波动当确定异常。“本期报告未出现”不等于需求消失。

广告位置按原始粒度标注活动级、广告组级或目标级，展示指标和份额变化。关键词只可引用所属活动位置作为背景，不把活动位置CPC归因到关键词。

## 指标、重复与原始来源

CTR=点击/曝光，CPC=花费/点击，广告CVR=广告订单/点击，ACOS=花费/广告销售额，ROAS=广告销售额/花费。先汇总分子分母再算比率，缺失或零分母显示不可计算；上期为0不显示无限增长。不同店铺、站点、币种、广告类型、归因口径独立分析。订单与销量分开，业务Unit Session %不当广告CVR。无相应证据不推断自然订单、自然排名或TACOS。

相同文件已保存时跳过重复；待确认重选更新预览；保存失败可重试。只去除原始整行完全相同的数据，不因未映射维度不同而误去重。重叠日期按同类型、同范围、同天的最新启用完整快照替换，不累加旧版或从旧版补回消失词。周期汇总只在整体范围匹配且原始行完整包含于该范围时使用，绝不按天均摊或拆周。不同筛选范围的后台导出需通过版本启停确认，系统不能推断文件中未声明的筛选范围。

原始二进制、标准化行、来源行号及历史版本在浏览器保存，可下载原文件。识别规则升级后重传同文件可重新解析，停用旧识别版本，历史不删除。

## 调整与导出

「记录调整」自动带入店铺、站点、活动、广告组、关键词、当期指标。用户补充实际做过的动作和日期后保存，才进入实际调整列表。点击入口和系统建议都不代表修改过亚马逊后台。

有同对象调整前后各7天的完整可比数据时显示前后指标；不足则待补充数据。前后变化不等于调整导致的效果，需检查同期其他影响。

「导出Excel」生成5个工作表：本周重点、关键词对比、搜索词对比、广告位对比、建议处理清单。保留范围、实际日期、币种、归因、活动/广告组、匹配、来源和依据。建议与页面同一规则，标为尚未执行。搜索词导出保留广告组明细，避免跨组执行。

## 数据保留

使用现有IndexedDB和旧版迁移机制，不清空已有产品、报表、事件、决策或建议。新增实际调整存入独立 `adjustments` 列表，旧 `actions`/`events` 不改作已执行操作。完整JSON备份包括原文件，旧备份仍可恢复。

数据只存当前浏览器、当前来源。换域名/浏览器或清理数据不会自动跟随。IndexedDB不可用时会明确警告；请定期导出备份。运行和导入不上传数据到服务器。

已使用用户提供的7份原始报表ZIP校准US$金额、放置列、混合SP/SB/SD、SB总计与点击限定字段、活动投放方式及缺失统计日期等情况。该ZIP含多日跨度汇总，已验证整期分析，不能据此证明精确周度变化。精确周度和调整后复盘还需每日粒度或两个完整独立周期的实际导出。原始文件及经营数值不提交到代码仓库。

## 开发验证

使用页面不需要Node。开发验证可运行 `npm test`。

浏览器检查仅在开发时需要Playwright、ExcelJS、JSZip及Chromium，通过拦截提供静态文件，不启动服务：

```sh
WORKBENCH_TEST_MODULES=/path/to/node_modules node checks/browser.cjs
WORKBENCH_TEST_MODULES=/path/to/node_modules node checks/import-retry.cjs
AMAZON_SAMPLE_ZIP=/path/to/reports.zip WORKBENCH_TEST_MODULES=/path/to/node_modules node checks/real-reports.cjs
```

覆盖一键部分成功导入、失败重试、重复去重、具体规则重点、紧凑表格、跨组隔离、5表Excel读取、简单调整及前后复核、已有历史和产品保留。算法测试涵盖聚合、缺失、日期、粒度、币种、归因和精准候选证据条件。

每个云任务已隔离，后续使用现有checkout，无需另建Git worktree。
