# 亚马逊运营工作台

纯静态 HTML / CSS / JavaScript，多店铺、多品牌、多站点。直接打开根目录 `index.html`，保留 `public/` 文件夹。也可将整个项目上传至静态托管平台；所有资源均为相对路径，支持子目录部署。不需要 Node 服务、构建或依赖安装，不连接 Amazon API，也不会自动修改广告。

## 两步使用

1. **收集表格**：首页拖入或一次选择后台原始 CSV、TSV、XLSX，或包含这些文件的 ZIP。按实际列名识别，不依赖文件名；XLSX 会读取全部非空工作表。CSV 支持 UTF-8、UTF-16 BOM、GB18030 回退、逗号/分号/Tab 分隔。旧式 `.xls` 暂不支持，请在 Excel 中另存为 `.xlsx`，无需转成模板。
2. **分析数据**：补充无法从文件确定的店铺、站点、币种、广告类型、归因口径及日期后保存，点击「开始分析」。查看投放关键词、顾客搜索词、广告位置、广告商品、活动及子ASIN业务数据。

常见中英文列名自动映射。无法确定的报告类型或字段可在原始列名/前3行预览中确认；同一列名组合的映射保存供下次使用。日期支持 ISO、Excel 日期及英文报告常见的月/日/年格式；对于日/月/年且无法明确判定的文件，请在源报告中改用 ISO 日期，避免误认。

## 支持的数据与计算

- SP/SB 搜索词报告、SP 投放/广告位置/广告商品报告、广告活动报告、业务子ASIN销售与流量报告；广告类型不明确时要求确认，不凭文件名认定。
- 缺少某报告不阻止其他分析。没有投放报告时可从搜索词报告按原投放目标汇总**报告可见流量**，明确提示这不等于完整投放表现。
- 7天、14天和自定义不重叠周期；默认结束日为所选范围内最新已结束的数据日，排除当天。显示覆盖天数与归因回补提醒。完整7天窗口足够时显示多周趋势。
- 先汇总分子分母，再计算 CTR、CPC、广告订单CVR、ACOS、ROAS。比率变化显示百分点；上期为0时不显示无限增长率。不同店铺、站点、广告类型、币种及归因口径独立分析。
- 订单与销量分别保留；业务 Unit Session % 使用业务销量/会话，与广告订单/点击的CVR严格分开。无适当数据不推断自然订单、自然排名或TACOS。
- 活动级位置数据只用于活动背景，不分摊给关键词；只有原始位置报告含目标交叉维度时才展示该层级。位置份额以已提供的同层级位置为分母。
- 搜索词汇总与广告组明细分开；“本期报告未出现”不等于搜索需求消失。缺失记录不补零。缺少某对象的上期数据时，不把它自动认定为0或新需求。
- 低点击量仅作样本量提示，不作为自动否词阈值。所有操作均需人工核对相关性、目标与历史信息。

## 重复、重叠与版本

原始文件内容相同会跳过重复上传，文件内部完全重复数据行也会去重并提示。原始二进制及每次更新版本保存在浏览器 IndexedDB，可下载原文件、停用/重新启用版本。

同一分析范围、同一报告类型、同一天，选择最新启用的**整天快照**，不会把两次导出的同一天累加，也不会将新版中已消失的搜索词从旧版补回。非重叠日期继续使用其最新来源。关键词优先由投放报告计算，搜索词/位置/业务等报告分开计算，不跨报告叠加花费。

完整每日覆盖与完整周期汇总均可用于精确匹配的周期，采用较新的完整来源；每日覆盖不完整但存在精确匹配汇总时使用完整汇总。仅有周期汇总时，必须与分析周期完全一致才使用，绝不按天均摊、拆周或把部分交叠汇总累加。

**范围限制**：后台报告可能只导出部分活动/广告组，文件本身未必声明筛选范围。请为同一范围上传完整快照；上传不同筛选范围的导出时，在收集清单停用不适用版本。工作台不会凭空推断未包含的活动是零投放。当前不合并部分筛选快照来猜测完整数据。

## 产品、历史与操作

原 Upelf 四条产品线、全部原ASIN、产品限制、历史成本售价、目标、关键词、问题、用户编辑的变体映射均保留。首次运行自动从旧版 `upelf-v1` 本地数据迁移（不删除旧存储），包括已有报表、实验、事件与建议。旧版未保存原文件，因此旧报表标记来源缺失。产品可全部编辑；新产品从空白字段创建，不继承 Upelf 专属结论。

关键词/搜索词明细可加入行动清单。行动保留活动/广告组名称和ID、问题、证据、可能原因、缺少证据、建议、状态、复盘时间。无活动或广告组定位的记录标记不可执行。分析/行动导出CSV仅用于人工审核，并非Amazon批量上传文件。

## 数据保存与边界

数据与原文件只存当前浏览器、当前来源的 IndexedDB。若浏览器不允许 IndexedDB，页面明确警告：仅元数据尽力保存至 localStorage，原文件暂存内存，刷新可能丢失。请定期导出**含原始文件**的JSON完整备份，支持恢复新版备份及旧版备份。更换浏览器、域名、文件路径或清理浏览器数据，不保证存储自动跟随。

单文件30MB，本批读取/解压总量80MB，ZIP最多50个非目录成员；不递归解压ZIP。XLSX公式仅使用已有缓存值，不执行公式、宏或外链。所有外部库已随项目本地附带，不需要运行时联网。

尚未获得卖家真实报表样本：目前验证使用常见Amazon原始列名的自动化测试文件，不能保证覆盖所有站点/语言/新版本字段。下一轮校准优先提供：SP搜索词报告、SP投放报告、SP广告位置报告各一份（原始CSV/XLSX，尽量每日粒度并覆盖两个完整周期）；如运营SB，再提供SB搜索词报告；业务指标校准提供子ASIN销售与流量报告。可以脱敏店铺和活动名，请保留原始列名、日期、行粒度及数值格式，无需填写模板。

## 开发验证

使用工作台不需要Node。有Node的开发者可以运行 `npm test` 验证列识别、缺失处理、归因隔离、周期汇总、去重更新、稳定ID及旧版迁移。

可选端到端检查脚本位于 `checks/browser.cjs`：需已有 Playwright、ExcelJS、JSZip 和 Chromium。脚本通过浏览器拦截直接提供静态资源，不启动HTTP/Node服务；只使用明确标记的测试样本，不含真实卖家数据。

浏览器脚本运行示例（在项目根目录，设置测试工具的真实安装目录）：

```sh
WORKBENCH_TEST_MODULES=/path/to/node_modules node checks/browser.cjs
```

测试依赖仅用于开发验收，不是工作台运行依赖。

每个云任务已经隔离，继续使用现有checkout，无需额外创建Git worktree。
